# 钢琴演奏速度调节

`performance` 是可选的演奏专用配置。旧配置不含该字段时保持原行为。Web「参数与标定 → 钢琴演奏专用速度」可修改，保存、重建会话后生效；曲谱 BPM 修改后须重新预检。

当前候选：SDK 10%、关节规划速度上限 0.225 rad/s、换位最短 0.45 s、到位后稳定 0.2 s、抬指最短间隔 0.12 s、按住最短时间 0.15 s。SDK百分比不等于实测角速度，软件到位也不等于琴键发声。

仅歌曲执行、标定区「测试单键移位」启用这组参数。准备、直接回演奏零位、MORLA工作位、钢琴回位及在线点动仍使用基础 `timing` 和原SDK速度。结束及健康停止后恢复原SDK速度；故障停止保留既有处理。SDK速度在现有位置模式下更新，不重新使能、不急停、不改变位置目标；相同保持目标仍去重。两臂速度的 SDK 调用成功状态被确认后才开始曲谱计时，等待期间持续保持目标。

换位使用三次平滑插值，时长为 `max(move_duration_s, 1.5*最大关节位移/max_arm_velocity_rad_s)`；稳定时间必须容纳持续到位时间与至少两个控制周期。同侧抬指、抬指等待、移位、稳定、再按下有严格顺序。另一侧空闲手可以在当前手弹奏期间换位；全局仍只按一键。BPM提高会缩短CSV中的空拍，不能跳过预检。

手指的目标角、悬停角、SDK增益和电流不因该配置改变。最短按住/抬指时间是调度限制，不能替代现场测量。双手到位检查依照此前设置继续关闭，不额外扩大限位或误差阈值。

## 建议现场验证

1. 刷新页面、建立会话，照原流程反馈、复位/检查、准备。先保持40 BPM，确认单指动作正常。
2. 在准备完成的位置，分别测试左右移位0→1→0。测试的是候选演奏速度，不需要重新走工作位；根据手指与琴键实际位置选择没有障碍的测试范围。
3. 原版《欢乐颂》设60 BPM，重新预检并演奏；观察按响、抬起、换位是否跟随。有异常立即停止本轮。
4. 60 BPM稳定后再测65 BPM。扩展版的候选理论上限约66 BPM，普通版约75 BPM；不要把理论上限作为真机推荐速度。
5. 若跟随慢，先看 SDK 已应用值、目标与实测曲线；若回弹慢，应降低BPM或增加抬指时间。不要用放宽到位/跟踪阈值掩盖。

会话目录的 `events.jsonl` 保存 `performance_speed`（切换确认）及 `speed_sample`（10 Hz目标、实测、按指状态、实测接收时间）。样本不塞入浏览器实时事件列表，减少页面开销。可分析实测变化和指令时间关系，但无法由这些样本证明琴键接触或音频质量。

离线对比命令：

```bash
python3 scripts/benchmark_speed.py --config ../MORLA/.morla_piano/config.json --output /tmp/piano-speed.json
```

该脚本不连接ROS或硬件，使用瞬时软件反馈完整执行曲谱并检查时序。SDK 5/10/15%切换另用隔离ROS域的fake驱动验证；不能据此断言真机速度倍数或最优百分比。

## 本轮真机记录

操作员报告测试成功、无卡顿。60 BPM原版《欢乐颂》两次演奏均完成，每次42个按下/抬起事件、5次换位，耗时56.089/56.096秒，无故障事件。演奏SDK10%、规划0.225 rad/s的配置可作为当前已测基线；结束后双侧SDK恢复5%。15%与更高BPM尚未进行真机验证，琴键接触/每音发声没有独立音频确认。服务器证据：`.morla_piano/diagnostics/speed_profile_20261022_230243/hardware_review.json`。
